# T01 — Identidade estável do entregável (`external_ref`)

## Identity

```text
feature_id: F-027
task_id: T01
parent_plan: docs/features/F-027-o-aceite-que-a-tela-so-desenhou/plan.md
depends_on: none
```

## Goal

`PhaseDeliverable` passa a ter uma coluna `external_ref` **durável** (o id do entregável no
Biahflow), e `sync_snapshot` a popula em toda sincronização. Depois desta tarefa, o mesmo entregável
lógico tem um identificador que **sobrevive** ao delete/recreate que o sync faz a cada snapshot —
pré-requisito para o aceite (T02) ancorar em algo estável, não no uuid do read model.

## Scope

- `apps/api/src/portal_api/models/project.py` — adicionar `external_ref: Mapped[str | None]` (ou
  `str`, se sempre presente) ao modelo `PhaseDeliverable`, no precedente de `PendingItem.external_ref`.
- `apps/api/src/portal_api/integrations/biahflow.py` — em `sync_snapshot`, ler o id do entregável do
  snapshot e gravá-lo em `external_ref` ao recriar as linhas de `PhaseDeliverable`.
- `apps/api/src/portal_api/db/migrations/versions/` — uma migração Alembic **aditiva** que adiciona a
  coluna (e índice se o precedente `PendingItem.external_ref` tiver um).

## Out of Scope

- A tabela `deliverable_acceptance` (T02), a rota/módulo (T03), a notificação (T04).
- Qualquer superfície de UI.
- Mudar o formato do snapshot do Biahflow (o id já vem; só passa a ser lido/persistido).
- Alterar a estratégia de replace do sync — só acrescentar a gravação do campo.

## Acceptance Criteria

- `PYTHONPATH=src alembic upgrade head` (de `apps/api/`, com `DATABASE_MIGRATION_URL`) aplica sem
  erro; `PYTHONPATH=src alembic check` reporta **sem deriva** entre modelos e migrações.
- `PYTHONPATH=apps/api/src pytest apps/api/tests/test_migration_rules.py` verde (a migração é
  aditiva — sem `drop_*` no `upgrade()`).
- Um teste de integração novo (em `apps/api/tests/`) prova que, após dois `sync_snapshot` do mesmo
  projeto, a linha de `PhaseDeliverable` correspondente mantém o mesmo `external_ref` (sobrevive ao
  delete/recreate). Rodável com `PYTHONPATH=apps/api/src pytest apps/api/tests/ -k external_ref`.

## Known Risks

- Se `external_ref` nascer `NOT NULL` sem default, a migração falha em base com linhas existentes —
  torná-la nullable ou popular na própria migração. O snapshot recria as linhas, então o valor chega
  no próximo sync; a coluna nullable é o caminho aditivo seguro.
- Um índice único sobre `external_ref` **sozinho** estaria errado (o mesmo id pode existir em
  projetos diferentes na origem? não — mas o escopo é tenant): se houver unicidade, é por
  `(project_id, external_ref)`, no precedente do `uq` de `agent_event`.

## Human Gates

- Merge da branch da tarefa é gate humano — o Builder abre PR, não mergeia.
- Nenhuma decisão de arquitetura nova aqui: a coluna e o precedente já estão na ADR 0077. Se o
  snapshot **não** trouxer o id do entregável (a inspecionar), isso é `BUILD_BLOCKED` com decisão
  para o lado Biahflow — não inventar um id.
