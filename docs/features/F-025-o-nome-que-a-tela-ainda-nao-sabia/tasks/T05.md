# T05 — A evidência de navegador

## Identity

```text
feature_id: F-025
task_id: T05
parent_plan: docs/features/F-025-o-nome-que-a-tela-ainda-nao-sabia/plan.md
depends_on: T01, T02, T03, T04
```

## Goal

Existe evidência congelada de que o que foi construído é o que foi aprovado, produzida contra a
**aplicação real rodando**, presa à revisão exata. `BROWSER_REQUIRED` não se satisfaz com suíte
unitária verde.

## Scope

| Arquivo | O que é |
| --- | --- |
| `scripts/capture-browser-evidence.mjs` | **novo** — dirige o navegador e captura |
| `docs/features/F-025-…/evidence/browser/**` | **novo** — as capturas e o manifesto |

`scripts/` é onde mora operação neste repositório, pela razão do `backup.sh`, do `loadtest.py`, do
`audit.mjs` e do `pins.mjs`. A captura é operação: determinística, sem modelo no laço.

## Out of Scope

- **Mudar código de produto para facilitar a captura.** Se um estado não é alcançável, isso é um
  achado a reportar, não um `data-testid` a inventar.
- **Alterar spec de e2e existente.** `npm run test:e2e` roda como está.
- **Encenar dado que a API não entrega.** A captura é do produto real com o seed real.

## Acceptance Criteria

1. **A pilha sobe e o e2e passa:** `docker compose up -d --build` e `npm run test:e2e` verde.

2. **As capturas existem, do produto real**, e cobrem o que a Issue #46 cobra:

   | Evidência | Viewport |
   | --- | --- |
   | shell do cliente — desktop | 1440 × 900 |
   | shell do cliente — mobile | 390 × 844 |
   | foco de teclado visível num controle real | 1440 × 900 |
   | dashboard/projeto com dado do seed | 1440 × 900 |
   | os quatro estados semânticos com ícone + texto + cor | 1440 × 900 |
   | estado de revisão/decisão do cliente | 1440 × 900 |
   | `/login` | 1440 × 900 e 390 × 844 |
   | a vitrine `/admin/design` | 1440 × 900 |

   O estado de revisão/decisão **não existe no produto** — é reservado pelo DAP. A evidência dele é
   a da vitrine, e o manifesto **diz isso**, em vez de deixar parecer que a tela existe.

3. **O foco é capturado por teclado de verdade** — `page.keyboard.press("Tab")` até o controle —,
   não por uma classe injetada. Foco que só existe porque o teste o desenhou não prova nada.

4. **Cada captura declara a revisão que a produziu.** Um `manifest.json` ao lado das imagens com o
   SHA de `git rev-parse HEAD`, a data, o viewport e a rota de cada uma. Evidência que aponta para
   revisão diferente da que está sob revisão é `REVIEW_EVIDENCE_INCOMPLETE`.

5. **Sem modelo no laço.** O script clica, espera e captura; nenhuma chamada a LLM. É a regra de
   FinOps de `browser-runtime-validation.md`.

## Validation

```text
baseline: com T01–T04 aplicadas, `npm run test:e2e` verde com a pilha de pé
required: e2e:     docker compose up -d --build && npm run test:e2e
required: browser: node scripts/capture-browser-evidence.mjs
```

O login usa Keycloak de verdade: as três contas semeadas estão em
`docs/runbooks/passeio-local.md`. Suba a pilha antes e espere `http://localhost:3000/login`
responder — subir o Keycloak leva mais que o resto.

## Context to Read First

- `tests/e2e/atores.ts` e `login.spec.ts` — como um ator entra pelo Keycloak de verdade.
- `tests/e2e/stack.ts` — `stackIsMissing` pula na máquina de alguém e **reprova no CI**, porque lá
  a pilha é subida pelo próprio job.
- `docs/runbooks/passeio-local.md` — quem é quem no ambiente local.
- `playwright.config.ts` — `baseURL` e `workers: 1`.

## Known Risks

- **A pilha demora.** O `ci.yml` espera `http://localhost:3000/login` num laço antes de rodar o
  e2e; faça o mesmo em vez de dormir um número fixo.
- **Captura pesa.** Use 1× e recorte por elemento onde a seção inteira não acrescenta; o pacote de
  design já custou megabytes ao repositório.
- **Um `docker compose` rodando do worktree** cria um projeto Compose diferente do checkout
  principal, com o mesmo par de portas. Suba de um lugar só.

## Human Gates

Se uma evidência exigida não puder ser produzida, **não a substitua por outra coisa**: reporte
`BUILDER_VALIDATION_BLOCKED`, liste o que ficou de fora e por quê, e nomeie `VALIDATE` em
`Unavailable capabilities`. Validação exigida que não roda não vira opcional.

## Reporting

Termine com o `BUILD REPORT` completo do contrato do Builder, com `browser_validation: executed`
e a lista de rotas e estados exercitados.
