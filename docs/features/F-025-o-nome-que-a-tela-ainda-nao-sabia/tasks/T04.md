## Goal

`/admin/design` existe e renderiza o sistema num navegador de verdade. É o que torna
`BROWSER_REQUIRED` verificável sem encenar estado raro em dado de produção: os quatro estados
semânticos, as quatro variantes de botão, o foco, os raios e a paleta ficam a um clique de quem
precisa conferir.

## Scope

| Arquivo | O que é |
| --- | --- |
| `app/admin/design/page.tsx` | **novo** — server component, resolve sessão e `is_internal` |
| `app/admin/design/DesignSystemClient.tsx` | **novo** — a vitrine, `"use client"` |
| `app/globals.css` | só se a vitrine precisar de classe nova |

## Out of Scope

- **Rota nova de API, esquema novo, ou qualquer leitura de dado de projeto.** A vitrine mostra o
  sistema, não o produto.
- **Logging.** Evento novo obriga linha em `docs/runbooks/alerts.md` no mesmo commit, e a guarda é
  bidirecional. Um alerta que ninguém vai vigiar é ruído, e esta tarefa não precisa de nenhum.
- **Link para a vitrine na navegação do cliente.** Ela é interna.

## Acceptance Criteria

1. **Autorização espelha `app/admin/page.tsx`**: resolve a sessão, busca `GET /api/v1/me` com o
   `authorizationHeader()`, redireciona para `/login` em 401, e chama `notFound()` para quem não é
   `is_internal`. É ergonomia, não segurança — a autoridade continua sendo a API, que responde 404.

2. **A vitrine renderiza, no mínimo:** as quatro pastilhas de `StatePill` (com ícone **e** texto),
   as quatro variantes de `Button` mais o estado `disabled`, um campo em repouso e um com foco, os
   três raios, a paleta com os valores e os pares de contraste medidos, e o `<Brand />`.

3. **Todo controle é de verdade.** `inertButtons()` isenta apenas `onClick=` e `type="submit"`.
   A vitrine demonstra estado **mexendo em estado** — um botão que alterna a variante em foco, uma
   pastilha que troca de tipo — em vez de desenhar botão morto. Isto não é para satisfazer a
   guarda: é o que a guarda existe para exigir (ADR 0026).

4. **Nenhum dado fixo de aba.** O corpus varrido reprova `const projects|notifications|documents|…`
   no topo de módulo. Constante de demonstração da própria vitrine (nomes de token, rótulos de
   variante) não é dado de projeto e é legítima — mas não use nenhum daqueles nomes.

5. **A regra de admissão ganha portão.** `docs/design/one-design-system.md` publica que "um token
   só entra no `@theme` se algum seletor o consumir", e a Issue #46 exige um *contrato estável de
   consumo de token para o trabalho futuro do One*. Regra publicada sem portão volta a divergir —
   é o argumento da ADR 0034, e o repositório inteiro é construído sobre ele.

   Acrescente a asserção em `tests/rendered-html.test.mjs` (é lá que mora a guarda de **forma** do
   lado web, ao lado de `inertButtons`):

   - **derive o corpus**, não digite lista: leia o bloco `@theme` de `app/globals.css`, extraia
     todo `--color-*`, `--radius-*`, `--shadow-*` e `--font-*`, e para cada um exija consumidor
     fora do próprio bloco — seja `var(--token)` no CSS, seja o utilitário que ele gera
     (`--color-info-600` → `text-info-600`/`bg-info-600`/`border-info-600`;
     `--radius-card` → `rounded-card`) em qualquer arquivo de `app/` ou `components/`.
   - **fail-closed**: corpus vazio reprova. Um `@theme` que a guarda não conseguiu ler tem de ficar
     vermelho, não verde — é o `dependency-review` da ADR 0023 outra vez.
   - **isenção é linha com motivo em prosa e sem prazo**, no precedente do `PINNED_BY_EXCEPTION`,
     com asserção de obsolescência: exceção que deixou de ser necessária reprova.

   **Meça a guarda por mutação antes de declarar pronto**, como a ADR 0065 exige: acrescente um
   token de mentira ao `@theme` e confirme que ela reprova; remova-o e confirme que ela volta ao
   verde. Reporte as duas saídas no `BUILD REPORT`. Uma guarda que nunca foi vista vermelha não é
   guarda.

6. **`npm run lint` e `npm test` verdes.**

## Known Risks

- **`export const dynamic = "force-dynamic"`** é o que `app/admin/page.tsx` usa, e pela mesma razão:
  a página é por usuário e por requisição.
- **A vitrine não deve virar segunda fonte de verdade dos tokens.** Ela lê o CSS pelas classes; se
  alguém escrever os hexes de novo dentro dela, a próxima mudança de token deixa a vitrine mentindo.
  Prefira `var(--color-…)` a hex, e a tabela de valores pode citar o token pelo nome.
