# T02 — Tabela `deliverable_acceptance` (append-only, imutável por privilégio)

## Identity

feature_id: F-027

## Goal

Existe uma tabela `deliverable_acceptance` que registra cada decisão de aceite do cliente como uma
linha **append-only, imutável por privilégio** (o app role recebe `SELECT, INSERT` e **nada** de
`UPDATE`/`DELETE`), escopada a organização+projeto. Uma segunda decisão **acrescenta** uma linha; a
anterior nunca é reescrita. É a fonte da verdade do aceite (ADR 0077).

## Scope

- `apps/api/src/portal_api/models/` — modelo `DeliverableAcceptance` herdando `_ProjectChildMixin`
  (`organization_id` + `project_id`), com: `deliverable_external_ref` (String, o vínculo estável de
  T01), `phase_name` e `deliverable_name` denormalizados, `action` (enum
  `deliverable_acceptance_action` = `accepted | changes_requested`), `actor_user_id`
  (`ON DELETE SET NULL`), `actor_label` (String), `actor_is_internal` (bool), `comment` (String,
  nullable), `created_at`.
- `apps/api/src/portal_api/db/migrations/versions/` — migração aditiva que: cria o enum
  `deliverable_acceptance_action`, cria a tabela, liga RLS, cria as policies `TO portal_app`
  escopadas a org+project (cópia de `0021_pending_item_comment`), e faz
  `GRANT SELECT, INSERT ON portal.deliverable_acceptance TO portal_app` — **sem `UPDATE`/`DELETE`**.
  **O corpo da migração DEVE citar a ADR 0077** (portão `test_migration_rules.py`).
- `apps/api/tests/test_rls_isolation.py` — casos novos.

## Out of Scope

- A rota/módulo de escrita (T03) e a notificação (T04).
- Qualquer `UPDATE`/`DELETE` grant — a imutabilidade é a ausência deles, de propósito.
- `superseded`/`cancelled` no enum — fora do desenho aprovado (§10); não adicionar.
- UI.

## Acceptance Criteria

- `PYTHONPATH=apps/api/src pytest apps/api/tests/test_migration_rules.py` verde: a migração é aditiva
  e, por tocar `CREATE POLICY`/`GRANT`, **cita a ADR 0077** no corpo (o teste falha sem a citação).
- `PYTHONPATH=apps/api/src pytest apps/api/tests/test_rls_isolation.py` verde, com casos novos que
  provam: (a) `INSERT` de `deliverable_acceptance` para outro tenant é rejeitado; (b) o app role
  **não consegue** `UPDATE`/`DELETE` a linha (`permission denied`) — a segunda decisão só pode
  acrescentar. Requer Postgres + papéis locais (`docker compose up -d postgres db-bootstrap`).
- `cd apps/api && PYTHONPATH=src alembic upgrade head` aplica; `alembic check` sem deriva.
- O meta-teste de RLS (`test_rls_isolation.py`) que exige policy para toda tabela com
  `organization_id` continua verde (a tabela nova a tem).

## Context to Read First

- ADR 0077 — §"Decisão" item 2 (a forma da tabela, GRANT só de INSERT).
- **Precedente A** — `pending_item_comment`: `models/project.py` (o modelo) e
  `db/migrations/versions/0021_pending_item_comment.py` (policies `TO portal_app` org+project,
  `GRANT INSERT`, sem UPDATE/DELETE; e o `ALTER TYPE ... ADD VALUE` fora da transação, se aplicável).
- **Precedente B** — `conversation_message.feedback` GRANT de coluna em
  `db/migrations/versions/0012_conversations.py` (só se houver campo mutável — aqui **não** deve
  haver, para manter a imutabilidade).
- `CLAUDE.md` §"Tenancy" — o meta-teste `test_rls_isolation.py`, o `search_path` não-qualificado,
  e a regra "toda tabela com `organization_id` ship com policy na mesma migração".

## Known Risks

- Esquecer que enum novo do Postgres se cria à parte (não só no Python) — a migração precisa
  `CREATE TYPE deliverable_acceptance_action AS ENUM (...)` (ou o helper do projeto).
- Conceder `UPDATE`/`DELETE` "por conveniência" quebra a imutabilidade e o teste de RLS deve pegar —
  não conceder.
- Policy `TO portal_app` faltando faria a tabela sumir do read do cliente (como `agent_api_key`);
  aqui o cliente **precisa** ler o histórico, então a policy de `SELECT` é necessária.

## Human Gates

- Merge é gate humano.
- A migração toca policy/RLS/GRANT → **cita ADR 0077** (que existe e está aceita). Não criar decisão
  arquitetural nova; se algo exigir uma (ex.: unicidade por `(project_id, deliverable_external_ref,
  created_at)`), parar e reportar, não decidir.
